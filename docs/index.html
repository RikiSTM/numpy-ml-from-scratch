🧮 NumPy ML From Scratch

Rebuilding core machine learning algorithms on pure NumPy — to understand the matrix math, not hide behind a library.

NumPy ML From Scratch is a machine learning project by Riki Sutiaman, an AI/ML engineer with 10 years of QA experience. It explores fundamental NumPy matrix operations by dissecting and rigorously testing core machine learning algorithms — without relying on high-level libraries.

🎯 The "Why"

Before trusting any ML framework, you must understand what's happening inside the matrix multiplications. This project strips machine learning down to its core — building Linear Regression, Logistic Regression, L1/L2 Regularization, and Decision Trees entirely from scratch. Every algorithm is accompanied by comprehensive unit and integration tests to ensure mathematical correctness, not just "it ran without errors."

🛠️ Core Algorithms

  • Linear Regression (from scratch): Built via closed-form normal equation and gradient descent — vectorized with pure NumPy matrix operations.
  • Logistic Regression (from scratch): Sigmoid activation, binary cross-entropy loss, and gradient computation implemented without sklearn.
  • L1 (Lasso) & L2 (Ridge) Regularization: Demonstrated how each penalty term reshapes the loss landscape — sparsity vs. shrinkage.
  • Decision Trees: Recursive splitting with Gini impurity and information gain, built on explicit mathematical foundations rather than library calls.
  • Data Pipeline Rigor: Strict label_map consistency and vectorized I/O — no silent index-mismatch bugs during training.

💡 Design Philosophy

1. Understand the Math, Not the API

Every fit() call in a framework is a black box. Writing gradient descent, sigmoid, and regularization from scratch reveals why hyperparameters matter — not just that they exist.

2. Tests Are the Spec

Unit and integration tests double as documentation. If the gradient matches the numerical gradient to within tolerance, the math is correct — even when the model "looks fine" on a loss curve.

3. Vectorization = Correctness + Speed

Every algorithm uses matrix operations where possible. Pure Python loops are not just slow — they hide bugs that @ operator broadcasting makes explicit.
